# سيناريو اختبار Qhub الكامل

هذا السيناريو يمرّ على البرنامج كله كما يستخدمه الناس: الموظف، والعميل، والنظام الذي يرسل الملفات عن طريق الـ API، والأدمن. وتقدر تمشي عليه يدويًا خطوة خطوة، أو تشغّله آليًا في Chrome بأمر واحد.

## التشغيل الآلي

```sh
cd e2e
npm install               # مرة وحدة فقط
node scenario.js          # على http://localhost:8090 ؛ لعنوان ثاني: QHUB_URL=https://... node scenario.js
HEADED=1 node scenario.js # نفس الشي لكن تشوف المتصفح وهو يشتغل
```

- **النتيجة:** كل خطوة تطلع `PASS` أو `FAIL` مع السبب.
- **عند الفشل:** صورة الشاشة تُحفظ في `e2e/out/<رقم الخطوة>.png`، والنتائج كلها في `e2e/out/results.json`.
- **كلمة سر الأدمن:** تُقرأ من `deploy/secrets/admin_password`.
- **أثر التشغيل على البيانات:** كل تشغيل يستخدم أسماء جديدة، فتقدر تعيده كثير. يترك وراه ملفين: ملف الـ API اللي اكتمل تحميله على دفعات، وملف القفل.

## خارج السيناريو حاليًا

- **الدخول الموحّد (SAML):** مؤجّل، ومعطّل في البرنامج.
- **التخزين على S3:** الكود مكتوب، لكن ما جربناه على S3 حقيقي.
- **التشفير:** السيناريو يشتغل على النسخة اللي في Docker، والتشفير فيها مقفل (`QHUB_ENCRYPTION=none`). التشفير نفسه مغطّى في اختبارات `dotnet test`.
